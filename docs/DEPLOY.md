# Free deployment: Render + Neon

| Part | Host | Plan |
|---|---|---|
| Storefront + API (Express serves the built React app) | Render web service `anvaya` | Free |
| ML / BI service (FastAPI) | Render web service `anvaya-ml` | Free |
| PostgreSQL | Neon | Free |
| Daily event purge + model retrain | GitHub Actions (`.github/workflows/maintenance.yml`) | Free |

**Free-tier behaviour to expect**
- Render free services sleep after 15 idle minutes. The first visitor then waits about 30–60 s.
- The ML service has no persistent disk, so after each wake it retrains in the background, which takes about a minute on the free CPU.
  - While it does, recommendation rails use the API's popularity fallback.
  - "Frequently bought together" stays hidden until the model is ready.
- Render gives 750 free instance-hours a month per workspace, shared by both services. Don't add keep-awake pingers.
- Free limits change; check the current Render and Neon pricing pages.

## 1. Database (Neon)
1. Create a project at neon.com. A region near your users (e.g. Singapore) keeps latency low.
2. Copy the connection string. It looks like `postgresql://USER:PASSWORD@HOST/neondb?sslmode=require`.
3. From your machine, create the schema, catalogue and admin account:
   ```bash
   cd server
   DATABASE_URL='<neon url>' NODE_ENV=production ADMIN_EMAIL='you@example.com' ADMIN_PASSWORD='<strong password>' \
     JWT_SECRET='seed-only-placeholder-0123456789abcdef' npm run seed
   # optional synthetic history so the dashboard and ML have data (flagged is_demo; can be removed later).
   # Pass the SAME production/admin variables: seed:demo re-runs the catalogue seed, and without them it
   # would create the dev admin (admin@anvaya.local, publicly known password).
   DATABASE_URL='<neon url>' NODE_ENV=production ADMIN_EMAIL='you@example.com' ADMIN_PASSWORD='<strong password>' \
     JWT_SECRET='seed-only-placeholder-0123456789abcdef' npm run seed:demo
   ```
   - The demo data is about 50 MB, which fits the free plan.
   - To remove it later, delete the `is_demo` rows. The demo reset path in `server/seed/demo.ts` (`resetDemo`) does exactly that.

## 2. Render services (Blueprint)
1. Push this repo to GitHub (done).
2. On render.com, go to **New → Blueprint**, pick the repo, and Render reads `render.yaml`.
3. When prompted, fill in:
   - `DATABASE_URL`: the Neon string, for **both** services.
   - `ML_SERVICE_URL`: `https://anvaya-ml.onrender.com`.
     - If Render adds a suffix to the name, use the ML service's actual URL from its dashboard and redeploy `anvaya`.
   - The Razorpay keys and `SELLER_STATE` can be left empty.
4. `JWT_SECRET` and `ML_SERVICE_TOKEN` are generated by Render, and the ML service receives the same token automatically.
5. The first deploy runs the database migrations automatically, on API start.
6. Open `https://anvaya.onrender.com` and sign in at `/login` with the admin account from step 1.3.

### Payments
- **Default** is `PAYMENT_PROVIDER=none`. The store works, and checkout says payments are not configured.
- **For a working test checkout**, create a free Razorpay account and, in **test mode**, copy the key id and secret.
  - Set `PAYMENT_PROVIDER=razorpay`, `RAZORPAY_KEY_ID=rzp_test_…` and `RAZORPAY_KEY_SECRET`.
  - Add a webhook to `https://anvaya.onrender.com/api/payments/razorpay/webhook` for `payment.captured`, `payment.failed` and `order.paid`, and set `RAZORPAY_WEBHOOK_SECRET`.
- The dev `mock` provider is refused in production by design.

## 3. Scheduled maintenance (GitHub Actions)
1. In the GitHub repo, go to **Settings → Secrets and variables → Actions** and add:
   - secrets: `DATABASE_URL` (Neon), `ML_SERVICE_URL` (`https://anvaya-ml.onrender.com`), `ML_SERVICE_TOKEN` (copy it from the `anvaya` service's environment on Render);
   - variable: `MAINTENANCE_ENABLED` = `true`.
2. The workflow runs daily at 03:00 IST. It deletes events past `EVENT_RETENTION_DAYS` and asks the ML service to retrain. You can also run it manually from the Actions tab.

## Troubleshooting
| Symptom | Check |
|---|---|
| Deploy fails at start with "Invalid environment configuration" | A required env var is missing: `DATABASE_URL`, `JWT_SECRET` (≥32 chars). |
| Recommendation rails show only popular items | The ML service is waking or training. Check `https://anvaya-ml.onrender.com/health` (`model_loaded`). Also confirm `ML_SERVICE_URL` and the shared token. |
| Admin "Recommendations & BI" page says ML service unavailable | Same as above. The first request after sleep can time out; reload after a minute. |
| Logged out immediately on the live site | Expected if `JWT_SECRET` changed (all sessions are invalidated). Cookies are `Secure` in production, so HTTPS is required (Render provides it). |
